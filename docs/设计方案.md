## 一、这东西到底怎么工作

一句话：**盯住一个目录，文件一变就把「那一刻整个目录的样子」拍成一张底片，每个文件单独用 AES-256 加密存起来，原始文件删了你还能翻回去挑一个时间点捞出来。**

三个核心概念：

| 概念 | 是什么 | 好处 |
|---|---|---|
| 内容块（blob） | 文件内容算 SHA-256 后按哈希命名，加密存储 | 同样的内容只存一份，天然去重；**只增不改，绝不覆盖** |
| 快照（snapshot） | 某一时刻的全部文件清单：相对路径 → 内容哈希 | 想看「上周三长什么样」翻快照就行，占空间极小 |
| 胶囊库（vault） | 所有块 + 所有快照 + 加密密钥参数 | 一个目录全带走，换机器输密码就能开 |

关键点：**快照是全量的，存储是增量的**。改一个 10MB 的 Word，快照只多出一个块，不是整目录再拷贝一遍。

## 二、目录结构

```
<你选的位置>\TimeCapsule\
  vault.json                 库配置：盐值、迭代次数、密码校验块、监控目录、策略
  blobs\a3\a3f8c1....tcb    加密后的文件内容（按哈希分两层目录，防单目录几十万文件）
  snaps\20261101-142530-001\
      manifest.json         这一时刻的完整文件清单
  logs\backup-202611.log    运行日志（明文，只记路径和结果，不记内容）
```

`manifest.json` 大概长这样：

```json
{
  "id": "20261101-142530-001",
  "takenAt": "2026-11-01T14:25:30+08:00",
  "sourceRoot": "D:\\Work\\Project",
  "trigger": "watch",              // watch 变化触发 / timer 定时触发 / manual 手动
  "fileCount": 128,
  "totalBytes": 47185920,
  "entries": [
    { "path": "src/Main.cs", "hash": "a3f8c1...", "size": 2048,
      "mtime": "2026-11-01T14:20:11+08:00", "blobSize": 2096 }
  ],
  "prev": "20261101-135011-001"    // 上一张快照，方便算增量
}
```

## 三、加密方案（逐个文件，不是一个打包加密）

- 算法：**AES-256-GCM**（.NET 内置 `AesGcm`，带完整性校验，密文被改一个字节就解不开，不会给你半个坏文件）
- 密钥：你设一个主密码 → PBKDF2-HMAC-SHA256（210,000 次迭代 + 32 字节随机盐）派生 256 位主密钥。密码不落盘。
- 每个文件：随机 12 字节 nonce，独立密钥（主密钥 + 文件哈希 HMAC 派生）→ 一个文件被爆破不影响其它文件
- 块文件格式：`TCV1`(4B 魔数) + `版本`(1B) + `nonce`(12B) + `tag`(16B) + 密文
- 密码校验：库里加密一段固定文本，输错密码直接提示，不靠"试到一半报错"
- 加解密全程流式（分块读写），几个 G 的大文件也不会把内存撑爆

**改密码**：只需重新加密「主密钥」那一小段（做一层密钥包裹），不用把所有文件重读一遍重加密。

## 四、监控与定时

1. **FileSystemWatcher 实时监控**（含子目录），事件来了先**防抖 5 秒**——你保存文件时 Word 会连续产生一堆临时文件，不防抖就会一秒一张快照。
2. **定时兜底**：默认每 30 分钟全量扫描一次，抓 FileSystemWatcher 漏掉的变化（网络盘、某些写入方式会漏）。
3. **内容没变就不拍**：扫描后如果所有文件的哈希和上一张快照完全一致，直接跳过，不产生空快照。
4. **内部工具产生的临时文件自动排除**：`*.tmp` `*.crdownload` `*.part` `~$*.docx` `.git\` `node_modules\` 等，可在设置里改。
5. 备份过程在后台线程串行执行，绝不阻塞界面；同一时刻只允许一个备份任务。

## 六、恢复流程（防手滑设计）

1. 左边点一个快照 → 右边列出当时的全部文件（可以按名字搜索、按大小排序）
2. 恢复范围二选一：**恢复整个快照** / **只恢复勾选的文件**
3. 恢复目标二选一：
   - **恢复到新目录**（默认，推荐）：`D:\恢复\20261101_1425\`，原样还原目录结构，**绝不碰你的现有文件**
   - **覆盖回原位置**：需要额外勾一个「我知道会覆盖」确认框，且覆盖前把被覆盖的现有文件先挪到 `回收-时间戳\` 里，不做真删除
4. 恢复后弹结果：成功 N 个、跳过 N 个（同名已存在）、失败 N 个（附原因），可导出清单
5. 恢复过程若校验失败（解密 tag 不对 / 哈希对不上），该文件标记为「损坏」并继续处理下一个，不会整体中断

## 七、技术细节确认（这些我按最优选，你不同意就说）

- **多实例**：全局互斥锁，库被另一个实例占用时明确提示，不会两个进程同时写坏库
- **断电容错**：加密块先写 `.part` 再原子改名；manifest 最后写，并带 CRC。中途断电最多丢最后一张快照，库不会坏
- **空间治理**：库设置页显示占用、块数、去重节省了多少；提供「清理旧快照」策略
- **日志**：按月分文件，只记操作和错误，不记文件内容
- **单文件排除上限**：超过 N MB（默认 500）的文件跳过并在日志记一条，避免一个 ISO 拖垮备份
- **自检**：内置「库完整性检查」按钮——遍历所有块校验 tag 和哈希，出报告
- 出包：`dotnet publish -r win-x64 --self-contained true` 绿色目录，双击就跑，目标机不用装 .NET；可选单文件 exe

## 八、验收清单（我会自己先跑通再给你）

1. 建库 → 设密码 → 输错密码被拒、输对能进
2. 监控目录新增/修改/删除文件 → 5 秒内自动出快照，界面时间轴实时多一条
3. 内容未变的定时扫描 → 不产生空快照
4. 大文件（>100MB）备份不卡界面、内存稳定
5. 改一个文件 → 新快照只多一个块，库体积增量 ≈ 该文件大小
6. 从旧快照恢复单个文件到新目录 → 内容与原文件 **SHA-256 完全一致**
7. 从旧快照恢复整个目录 → 文件数、结构、内容全对
8. 手工篡改一个 blob 文件 → 恢复时该文件报损坏，其它文件正常恢复
9. 覆盖回原位置 → 被覆盖的旧文件出现在「回收-时间戳」里
10. 关闭软件重开 → 快照、配置、密码全部保留，接着监控

## 九、待你拍板（这几个点定了我就开工）

1. **密码怎么用**：A. 设一次主密码，以后打开软件自动用（省事，但别人拿到你电脑就能解）；B. 每次启动输一次（安全）；C. 设一次主密码 + 可勾「记住」（折中，我倾向 C）
2. **库放哪**：默认 `D:\TimeCapsule`（D 盘有 430G 空闲）。要不要支持多个库（比如工作一份、家里一份）？
3. **保留策略**：A. 一张都不删，你自己手动清（最安全）；B. 自动保留最近 30 天整天 + 每天最后一个，更早的自动清；C. 只按总量上限清最旧的。默认 A，你选。
4. **默认备份间隔**：30 分钟？变化即备份的防抖 5 秒够不够？
5. **界面选 A（三栏工作台）还是 B（上下分区）**？
6. **是否需要**：托盘常驻 + 开机自启 + 备份完成气泡提示？（默认做托盘，自启做成勾选项）
7. **要不要"加密的备份也能导出成未加密 zip"** 这种功能？（安全上是个漏洞，我倾向不做）
